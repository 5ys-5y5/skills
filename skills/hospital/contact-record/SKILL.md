# 상담 기록·콜백 요청

## 시작할 때

사용자가 제시한 페이지 또는 현재 작업 환경에서 안내한 CRM을 연다. 접속 정보·권한·인증 수단은 호출한 에이전트가 자신의 환경에서 확인해 사용한다. 이 스킬은 설정 파일의 위치, 키 이름, 비밀 저장 방식, 전용 API를 정하지 않는다.

이미 해당 병원·업무 계정으로 로그인되어 있으면 세션을 재사용한다. 로그인이나 추가 인증이 필요하면 현재 환경이 제공하는 수단을 따른다. 화면에서 식별 가능한 필드는 별도 매핑 파일 없이 사용한다. 요청에 꼭 필요한 정보만 부족할 때 확인한다.

현재 환경에 실제 제공된 브라우저 도구를 사용한다. 관찰한 페이지에서 대상을 식별하고 도구의 입력 규격에 맞춰 조작한다. 특정 도구 이름이나 자체 실행·검증 도구가 반드시 존재한다고 가정하지 않는다.

## 업무 처리

1. 상담 대상, 요청 내용, 실제 수행한 조치, 확인한 결과와 후속 요청을 구분한다. 익명 문의를 허용하는 환경이라면 환자 등록을 강제하지 않는다.
2. 기존 기록 수정 요청이거나 현재 대화에서 생성한 기록번호가 있으면 해당 상세를 먼저 연다. 새 기록 전에는 대상·발생시각·요청 내용으로 최근 기록을 대조하되 비슷한 내용만으로 별개 상담을 중복으로 단정하지 않는다.
3. 요청 내용·조치·결과를 사실대로 기록한다. “예약 변경 요청”과 “예약 변경 완료”를 구분한다.
4. 콜백 요청이면 실제 담당자/부서 선택지와 필요한 기한·연락 방법을 확인하여 대기 상태로 등록한다. 담당자 수신·처리 근거 없이 콜백 완료로 표시하지 않는다.
5. 저장된 상담 상세를 다시 열어 대상 연결·내용·후속 상태를 확인한다. 저장이 불명확하면 먼저 조회하고 중복 생성하지 않는다.

완료 기준: 요청한 기록 또는 콜백 요청이 CRM에 존재하고 내용이 일치한다. 실제 전화·문자 발송은 별도 조치다.
예: “상담 결과를 기록하고 원무팀에 내일 오전 콜백을 요청해 주세요.”

## 실패와 결과 불명

명확한 입력 오류는 해당 항목을 고쳐 다시 제출할 수 있다. 저장 성공 여부가 불명확하면 현재 상태를 조회한 뒤 판단하고 즉시 같은 조치를 반복하지 않는다. 확인할 수 없는 결과는 확인 불가로 설명한다.
