# 내원·접수

## 필수 선행조건

이 문서를 직접 요청받아도 먼저 상위 진입점의 매핑·호출 검증 절차를 따른다. [선행 검증](../../prerequisites.md)과 이 업무의 contract.json으로 mapping_valid를 확인한 후에만 업무를 시작하고, 실제 조작은 매번 action 검증의 ready 이후에 수행한다. 결과는 result.schema.json과 요청한 result_fields로 검증한다. 필수 XPath나 값이 없으면 업무를 진행하지 않고 매핑 정의로 돌아간다.

## 시작할 때

사용자가 제시한 페이지 또는 현재 작업 환경에서 안내한 CRM을 연다. 접속 정보·권한·인증 수단은 호출한 에이전트가 자신의 환경에서 확인해 사용한다. 이 스킬은 설정 파일의 위치, 키 이름, 비밀 저장 방식, 전용 API를 정하지 않는다.

이미 해당 병원·업무 계정으로 로그인되어 있으면 세션을 재사용한다. 로그인이나 추가 인증이 필요하면 현재 환경이 제공하는 수단을 따른다. 조작 전에 [업무 항목과 화면 요소 대응 기준](references/ui-mapping.md)을 읽고 요청 업무에 필요한 매핑을 확인한다. 요청에 꼭 필요한 정보만 부족할 때 확인한다.

현재 환경에 실제 제공된 브라우저 도구를 사용한다. 관찰한 페이지에서 대상을 식별하고 도구의 입력 규격에 맞춰 조작한다. 특정 도구 이름이나 자체 실행·검증 도구가 반드시 존재한다고 가정하지 않는다.

## 화면 매핑 확인

업무 조작은 검증을 통과한 profile의 XPath와 역할만 사용한다. 현재 환자·예약·청구·상담 상세에 해당하는 범위인지 실제 관찰로 확인하고 다음 조작을 action 검증한다. 화면이 달라지거나 대응이 없으면 임의 요소를 선택하지 않고 상위 진입점의 매핑 정의·검증 단계로 돌아간다.

첫 번째 일치 요소를 임의 선택하지 않는다. XPath가 유일해도 의미·소속 확인이 필요하다. 새 필드나 선행 버튼이 필요하면 먼저 profile에 등록하고 관계 검증을 통과시킨다. 요청에 필요한 입력값도 검증된 뒤에만 사용한다.

## 업무 처리

1. 환자를 특정하고 대상 예약 또는 당일 진료 건을 확인한다. 오늘의 날짜와 초진·재진 판정은 현재 병원 시간대·진료 이력·운영 기준을 따른다.
2. 기존 도착·접수 상태를 조회한다. 동일 진료 건이 이미 접수됐다면 새로 만들지 않고 현재 접수번호와 상태를 안내한다.
3. 도착 확인과 진료 접수를 구분하여 요청한 조치만 수행한다. 접수에 필요한 진료과·의료진 등은 화면 선택지와 요청값을 대조한다.
4. 진료 완료·귀가 등 종료된 건을 임의로 대기 상태로 되돌리지 않는다. 현재 상태에서 처리할 수 없으면 이유와 가능한 다음 조치를 안내한다.
5. 같은 예약/접수 상세를 다시 열어 환자·당일 날짜·진료과·의료진·저장된 상태를 확인한다.

완료 기준: 대상 당일 진료 건에 요청한 도착 또는 접수 상태가 저장됐다. 실제 대기 순서는 확인한 경우만 안내하고 대기시간을 추측하지 않는다.
예: “오늘 예약한 이 환자를 도착 처리해 주세요.”

## 실패와 결과 불명

명확한 입력 오류는 해당 항목을 고쳐 다시 제출할 수 있다. 저장 성공 여부가 불명확하면 현재 상태를 조회한 뒤 판단하고 즉시 같은 조치를 반복하지 않는다. 확인할 수 없는 결과는 확인 불가로 설명한다.
